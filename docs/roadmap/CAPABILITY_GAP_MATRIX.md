## 5. Prioritized gaps for cycle planning

**Critical (block later gates)**

1. C1: canonical contract set — most exist _inside_ PortalApi/1 or implicitly; need standalone versioned schemas without breaking the vendored surface.
2. C2: `.env` intelligence (discovery/validation/migration) — bootstrap-only today.
3. C2: cross-repo install planner + offline bundle — plan is per-repo today.
4. C4: adapter fidelity verification per Forja (each claims ops; evidence is per-Forja tests, not run here).

**High** 5. C5: self-healing risk classes + execution center + local observability surface. 6. C3: 360° multi-forge dashboard — portal currently serves one Forja; aggregation model undecided (ADR needed: the-forge as federator vs multi-portal discovery). 7. C3: frontend unit coverage (3 spec files today). 8. Homologation: performance baselines never measured; security test matrix partially covered (server-level pytest covers most; penetration items like symlink-escape/SSRF need explicit cases).

**Medium** 9. C2: recommendation engine (deterministic core absent). 10. C5: version manager beyond git pins. 11. C4: host integration beyond observe+launch-hint (documented limitation, honest today). 12. Homologation: concurrency/locking between CLI processes unimplemented; e2e not wired into `npm test`; macOS unverifiable here.
