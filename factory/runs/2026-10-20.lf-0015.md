## Não feito / riscos abertos

- `update <dir>` exige a fonte MAIS NOVA como argumento (semântica do
  spec dentro das opções existentes): `update <nome>` em fonte gitless é
  recusa nomeada que aponta `source_dir` — não há "pull sem git" por
  construção.
- Fallback `scripts/forge_bootstrap.py` só roda quando `resolvePython()`
  acha interpretador; sem ele + sem script POSIX/Windows = recusa
  `FORGE-SOURCE-INVALID` com remédio (documentado no código; o hook
  `install.windows.sh` via Git Bash fica para lf-0018, conforme audit).
- `CONFLICTING_IDENTITY` cobre basename-de-catálogo e identidade interna
  contraditória do manifesto; conflitos semânticos mais sutis
  (estrutura que "parece" outra Forja sem token de catálogo) ficam como
  identidade B/C honesta, sem falso conflito.
- `--method git` em `install <dir>` GIT_REPOSITORY: o detector aceita e
  o bootstrap roda no lugar (não há clone — coerente com "fonte local"),
  mas a semântica `--method git` para dir é ambígua; hoje só fonte sem
  `.git` + `--method git` é recusada.
- 5 docs de `docs/cycle12/` falham `prettier --check` desde antes desta
  run — formatação herdada, fora do escopo.
