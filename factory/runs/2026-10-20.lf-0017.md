# Run — lf-0017 (Universal Python discovery + interpreter validation + explicit selection)

## Entregue

- `src/env/python.ts` (novo) — pipeline `discoverPythons(deps)` em 8
  estágios determinísticos: `FORGE_PYTHON` (0) → `--python` (1) →
  launcher `py` do Windows (`py -3.14`…`py -3.10`, `py -3`, `py -2`, `py`)
  (2) → nomes do PATH `python3.14`…`python3`, `python` (3) → venv ativa
  `VIRTUAL_ENV` + `.venv`/`venv` do alvo (4) → version managers
  pyenv/uv/conda/mamba/asdf (5) → locais de plataforma (AppData/Program
  Files + registry PEP 514 read-only no Windows; `/usr/bin`,
  `/usr/local/bin`, `/opt/*/bin`, Homebrew/Linuxbrew no POSIX) (6) →
  `./python*`, `./tools/python*` (7). Cada candidato é validado
  EXECUTANDO `<argv> --version` com `PYTHON_PROBE_TIMEOUT_MS = 5_000`;
  a versão sai só da saída (`Python X.Y.Z[pre]` → `parseVersion`), nunca
  do nome/path. Vereditos: `ok|absent|unexecutable|incompatible|
  store-stub`; nomes do PATH resolvem antes via `command -v`/`where.exe`
  (não-resolvido = `absent`, não quebrado). Aliases `WindowsApps` que não
  produzem versão = `store-stub`/`FORGE-PYTHON-NOT-FOUND`; instalação
  real da Store que responde passa. Dedup por realpath resolvido + args
  da invocação (specs `py -3.x` são interpretadores distintos), budget
  `PYTHON_DISCOVERY_MAX_CANDIDATES = 32` com `truncated` reportado.
  Explícito inválido recusa com o FORGE-PYTHON-* do veredito e NUNCA cai
  para a auto-descoberta; `FORGE_PYTHON` vence `--python`. Auto =
  maior versão compatível com o piso (`DEFAULT_PYTHON_FLOOR = '>=3.10'`,
  estável antes de pré-release, empate por estágio e path). Tudo
  injetável (`platform/env/run/exists/readdir/realpath/osHome/cwd/
  targetDir/explicit/floor/maxCandidates`) — offline e read-only.
- `src/errors.ts` — `FORGE-PYTHON-NOT-FOUND`,
  `FORGE-PYTHON-INCOMPATIBLE`, `FORGE-PYTHON-UNEXECUTABLE`.
- `src/cli-args.ts` — `--python <exe>` parseado e documentado no help.
- `src/env/discover.ts` — relatório `forge/EnvironmentDiscovery/v1`:
  `python` ganha `source`, `selection_reason`, `pipeline: 'lf-0017'`,
  `candidates_total`, `candidates[]` (cap `PYTHON_REPORT_MAX = 24`) com
  `source/version/valid/verdict/code/note` e `refusal`. `pythonProbe`
  legado vira `PythonDiscovery` sintético (testes antigos intactos);
  refusal vira blocker/warning com código + remédio; pip probado via o
  interpretador SELECIONADO (`<sel> -m pip --version`) quando fora do
  PATH.
- `src/cmd/env.ts` — `env discover` honra `--python` (`pythonExplicit`).
- `src/cmd/registry.ts` — `probePythons` legado (`(exe,args)→string`)
  adaptado sobre o pipeline (probe `--version` decide; `command -v`
  identidade); `registryPythons` = descoberta com `cli.python`;
  install/lock/update/reinstall/rollback recusam com
  `${refusal.code}: ${refusal.cause}` + remédio; fallback sem refusal
  emite `FORGE-PYTHON-NOT-FOUND` nomeado.
- `src/registry/install.ts` — `PythonReceiptInfo
  {source,version,executable,selection_reason}`; `receipt.python`
  aceita objeto novo OU string legada; `receiptPythonInfo()` normaliza
  na leitura (`loadForgeState` — nunca regrava); seleção usa o piso do
  entry + `requires_python` resolvido.
- `src/source/install.ts` — `LocalPython`/argv legado via
  `localPythonOf()`; bootstrap `forge_bootstrap.py` usa o interpretador

  `pyproject.toml`; pip/venv probam o interpretador selecionado (ou o

- `src/utils/system.ts` — `resolvePython()` = `discoverPythons().selected.argv`.
- `src/index.ts` — `--python` no fluxo git/clone avisa que não se aplica

- Schemas — `contracts/schemas/ForgeEnvironmentDiscovery.v1.json` e o
