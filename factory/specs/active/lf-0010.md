# Context

`doctor` (lf-0007) diagnoses; `checkRepoPrereqs` (lf-0009) enforces declared
requirements. Two gaps: doctor can't heal — users must rerun the whole
install for one broken repo; and the python probe checks only
`python`/`python3`/`py` while `setup.ps1` resolves versioned interpreters
(`py -3.12`), so the check can false-fail a machine that would succeed.

# Grill Gate

- `--fix` scope: **full pipeline** — reuse `processRepo` wholesale
  (pull → env → configs → prereqs → setup → npm → verify). One code path.
- Python probes: **versioned** — try `py -3.14`…`py -3.10` (win32) and
  `python3.14`…`python3.10` (POSIX); pass when ANY interpreter meets the
  floor. pip/venv probes use the satisfying exe.
- Implementer: Devin.

# Acceptance Criteria

- [ ] `forge-cli doctor --fix` (positional `doctor` + new `--fix` flag):
      runs `runDoctor`; repos with status != 'ok' (fail) are re-processed
      via `processRepo` (existing checkouts → pull path); skipped repos
      (no checkout) are NOT cloned — reported as needing a full install.
      Re-run results shown in the standard report; exit 0 only when all
      repos end ok.
- [ ] `pythonInfo()` (or a new `resolvePython`) gains versioned probing:
      candidates ordered newest-first: win32 `py -3.14`…`py -3.10` then
      bare `python`/`python3`; POSIX `python3.14`…`python3.10` then
      `python3`/`python`. Returns `{ exe, args, version }` (args needed
      for `py -3.x` two-token invocation).
- [ ] `checkRepoPrereqs` python check passes when ANY candidate satisfies
      the floor — detail shows the satisfying exe+version; pip/venv
      probes run against that exe (with its args). Falls back to the
      default python row when no floor declared.
- [ ] Strings in `src/ui/strings.ts` (PT-BR) for fix mode labels,
      needs-full-install note, interpreter detail.
- [ ] `usage` documents `doctor --fix`.
- [ ] Tests: versioned probe ordering + any-satisfies logic (execa
      mocked), doctor --fix triggers processRepo on failures only,
      skipped repos not cloned, exit codes.

# Constraints

- `pythonInfo` stays backward compatible (preflight keep working —
  its 'first resolvable interpreter' semantics unchanged for the
  exists-or-not check).
- No new runtime deps; version compare reuses prereqs comparator.
