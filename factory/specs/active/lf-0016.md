# Grill Gate

- Owner: repo owner. Loop implements; product decisions stay human.
- Problem: installers and forge-cli assume "Windows = PowerShell" and
  "shell exists"; the prompt requires real capability discovery —
  PowerShell may be blocked/absent, Git Bash may be the sanctioned route,
  and WSL/Cygwin/MSYS2 are distinct shells, not interchangeable.
- Out of scope: WSL2 native automation (documented as "not equivalent to
  native Windows" — treated as Linux env, not a Windows fallback); any
  network detection; probing credentials/AD; bypassing corporate
  restrictions (FORGE-INSTALL-CORPORATE-RESTRICTION reports, not circumvents).
- Review failure: PowerShell absent → installer fails instead of
  Git-Bash route; Git Bash treated as interchangeable with WSL; preflight
  stops at first failure instead of reporting all; JSON report not
  schema-conformant; capability guessed instead of executed.
- Riskiest assumption: `bash -lc` inside Git Bash can probe python/git —
  mitigated by testing only commands actually needed and recording
  `command_probe` evidence per capability.
- Smallest acceptable: `forge/EnvironmentDiscovery/v1` JSON + shell routing
  (powershell → git_bash fallback) + aggregated preflight report.

# Context

prompt_evo_install.md FASE 2 + FASE 5 + FASE 6. Three pieces:

1. Shell capability discovery. Report `shells: {powershell, pwsh, bash,
   git_bash, wsl, cygwin, msys2}` each `{present, version, executable,
   probes: {...}}`. Windows route: PowerShell available → `install.ps1`;
   PowerShell absent AND Git Bash present → `install.windows.sh` (Git Bash
   route); both absent → FORGE-SHELL-NOT-FOUND with guidance. `pwsh` is
   detected separately from `powershell` (5.1 vs 7+); `wsl` reported but
   NOT used as a native-Windows substitute.

2. Preflight 2.0 — aggregated structured report:
   `{status, python, git, shells, network, disk, permissions, write_targets,
   forges_detected, blockers[], warnings[], recommendations[]}`.
   Runs ALL checks and lists all blockers — never stops at the first.

3. Path selection matrix (FASE 6): the set of paths an install writes to
   (venv/runtime dir, bin/shim dir, receipts dir, env vars) chosen by
   priority — explicit flags > env vars > user-level defaults > system
   defaults — with a `--print-paths`-style introspection so users see the
   chosen set before install. Restricted/permission-denied target →
   FORGE-INSTALL-PERMISSION-DENIED + concrete alternative path.

# Acceptance Criteria

- `forge/EnvironmentDiscovery/v1` emitted by `forge-cli doctor --json`
  (and/or a dedicated `env discover` verb) conforming to a checked-in
  schema; version-pinned.
- Shell detection distinguishes powershell/pwsh/git_bash/wsl/msys2/cygwin
  with probe evidence; Git Bash probe verifies bash execution, not just
  `bash.exe` presence.
- Simulated "PowerShell blocked" case (test injects PATH/execution-policy
  state) routes to Git Bash; simulated "no shells" yields
  FORGE-SHELL-NOT-FOUND with install alternatives.
- Preflight aggregates every check; a run with 3 problems reports 3
  blockers, not 1.
- Path selection honors the stated priority order; `--print-paths` (or
  doctor section) shows resolved targets; permission-denied target
  produces FORGE-INSTALL-PERMISSION-DENIED with the fallback suggestion.
- Windows unit tests exercise routing via injected env; POSIX unaffected.

# Constraints

- No execution of discovered tools beyond harmless probes (`--version`,
  `command -v`); timeouts on every probe (≤5s).
- Deterministic ordering in JSON output (sorted keys/lists).
- PT-BR user-facing messages; FORGE-* codes unchanged in both languages.

# Review Notes

Reject if: routing prefers WSL over Git Bash on Windows, preflight
short-circuits, probes run arbitrary commands, or the schema is not
committed and validated.
