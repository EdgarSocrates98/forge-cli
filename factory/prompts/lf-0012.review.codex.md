        # Context

Sequential processing of 8 repos ≈ 5 min. Two cheap wins: bounded
concurrency, and skipping repos whose HEAD hasn't moved since the last
successful run. `--shallow` (`git clone --depth 1`) speeds fresh installs.

# Grill Gate

- `--jobs` scope: **non-interactive only** (`--all`/`--only`/
  `--retry-failed`). Parallel output = plain log lines per repo
  (no clack spinner/taskLog multiplexing). Interactive mode ignores
  `--jobs` with a warning.
- `--only-changed` semantics: skip a repo when BOTH (a) `state.json`
  records last status `ok` and (b) stored HEAD SHA equals current
  `git rev-parse HEAD` after sync. Store `head` SHA in state on every
  successful run.
- Implementer: Devin.

# Acceptance Criteria

- [ ] `--jobs N` flag (int ≥1, default 1) + `jobs` config key. N>1 in
      non-interactive: worker-pool over repos (hand-rolled or
      `p-limit`-style loop — no new dep); per-repo log lines prefixed
      `[i/N] name — phase` instead of spinner/taskLog; results ordered
      by catalog order in the final report. Interactive + jobs>1 →
      warn `jobsIgnored` and run sequential.
- [ ] `--only-changed` flag + works with `--all`/`--only`: after sync,
      compare `git rev-parse HEAD` vs `state.repos[name].head`; skip
      when status was ok and SHA unchanged — skip reported as ok +
      note `unchanged`. Record `head` in `recordResult` (state.json
      gains `repos[name].head?: string`).
- [ ] `--shallow` flag + `shallow` config key: `git clone --depth 1`
      for fresh clones only (pull path unaffected).
- [ ] `syncRepo` gains options param (shallow flag); `CliState` type
      updated; usage + strings updated.
- [ ] Tests: jobs flag parse, interactive warning path, worker pool
      ordering + failure isolation, only-changed skip/pass logic with
      mocked SHAs, shallow clone arg, state head recording.

# Constraints

- Error isolation preserved — one repo's failure never aborts others.
- Log file + state recording still work in parallel mode (writes are
  append-based; prefix each line with repo name).
- `--jobs` capped at a sane max (e.g. 8) — invalid → CliError.
