# Acceptance Criteria

## `.env` bootstrap (new feature)

- After clone/pull and BEFORE the install script runs, each repo gets a `.env`:
  - `.env` already exists → leave untouched (`exists`), never overwrite.
  - `.env.example` exists (and `.env` doesn't) → copy to `.env` (`copied`).
  - Neither exists → write a `.env` stub containing only a PT-BR comment header telling the user to fill values (`stub`).
- Env provisioning failure (e.g. permission denied) → repo marked `[ERRO]`, install script skipped for that repo, other repos unaffected.
- The per-repo result and final report state what happened to `.env` (e.g. `.env criado a partir de .env.example`).

## Preflight checks (new feature)

- After the intro banner and before any prompt: verify `git` is runnable, Node >= 20, and — on win32 only — `powershell.exe` is resolvable.
- Each check shown with an icon line (✅/❌). Any failure → PT-BR error via `log.error` and exit code 1, before any prompt or filesystem change.

## UI/UX polish

- Centralized color theme (`src/ui/theme.ts`) wrapping picocolors: brand accent, ok/warn/err, dim helpers — used consistently everywhere.
- All PT-BR user-facing strings centralized in `src/ui/strings.ts`.
- Emojis: status icons ✅ ⚠️ ❌ in spinner stops and the final report; 🔥 (or forge-appropriate) in the banner/intro.
- Banner: figlet art printed with a per-line reveal animation (small delay between lines), then `intro()`.
- Each spinner stop and report line includes elapsed time per repo (e.g. `em 3.2s`).
- Final report keeps the `[OK]`/`[AVISO]`/`[ERRO]` semantics from lf-0001 (icons + labels), shows env detail, and ends with totals + friendly `outro()`.
- lf-0001 flow invariants preserved: default `./forge-workspace`, all-8 preselected multiselect, confirm before work, cancel/`SIGINT` exits cleanly.
