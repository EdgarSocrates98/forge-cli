# Acceptance Criteria

- `install.windows.sh` in forge-cli (and vendored to each forge repo
  where install.sh/install.ps1 live) passes `bash -n`; smoke-tested under
  the available MSYS-compatible environment or CI bash.
- Git-Bash route: python found outside PATH (via lf-0017) → venv created
  → forge runtime installed → receipt written → `forge doctor` passes.
- Receipt produced by install.windows.sh validates against the same
  schema as install.sh/install.ps1 receipts; fields equal modulo
  `execution_environment.shell`/`install_method`.
- Managed-artifact list identical semantics: uninstall via ANY route
  removes exactly the managed set, preserving planted user files.
- Env-var persistence on the Git-Bash route actually reaches Windows
  user environment (setx/HKCU or documented equivalent); POSIX route
  unchanged.
- Shared bootstrap: no per-shell fork of core logic; shell scripts only
  adapt invocation (path conversion `cygpath`, line endings, arg style).
- Every failure path emits FORGE-<CODE> + cause + remedy; negative tests
  cover gitless-dir, no-python, permission-denied, broken bootstrap.
- Cross-repo: canonical `forge_bootstrap.py` change (if any) lands in
  the-forge first, then vendored byte-identically + `_SOURCE_SHA256`
  restamped; data-sentinel-forge untouched.
