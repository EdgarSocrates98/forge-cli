        # Context

Two daily-driver gaps: no read-only view of the catalog + last-run status
(state.json already records it, nothing surfaces it), and repeated flags
(`--dir`, `--only`, `--timeout`, `--json`) must be typed every run.

# Grill Gate

- Config scope: **workspace only** — `forge-cli.config.json` in the target
  dir, same pattern as `forge-cli.repos.json`. No global file (chicken-and-
  egg with --dir; keep simple).
- Implementer: Devin.

# Acceptance Criteria

- [ ] `forge-cli list [--dir ..]` — table of catalog repos: kind icon,
      name, last status from `.forge-cli/state.json` (ok/warn/error/never
      run), timestamp. No side effects; exit 0.
- [ ] `forge-cli.config.json` in targetDir — optional; keys:
      `dir` (string), `only` (string[]), `timeout` (seconds number),
      `json` (boolean), `shallow` (boolean — reserved, no-op until
      lf-0012 lands it), `jobs` (number — reserved, same). Invalid file →
      warn + ignore (like custom repos). Workspace file only.
- [ ] Precedence: CLI flags > config file > built-in defaults. `only`
      from config selects repos when `--only`/`--all` absent; config
      `dir` is only meaningful for the *global default dir* case —
      resolve order documented in code.
- [ ] Load + merge in `src/config.ts` (new module) or extend artifacts;
      wired in `index.ts` after arg parse, before selection.
- [ ] Usage documents `list` and the config file.
- [ ] Tests: config parse/validate (invalid JSON, wrong types → ignore),
      precedence CLI>config>default, list output content with and
      without state.

# Constraints

- Config never overrides explicit CLI flags.
- Unknown keys tolerated (forward compat), required keys: none.
- Keep zero side effects in `list` (no state writes).

# Review Notes

- The `dir` key in a workspace config is inherently odd (you need the
  dir to find the file) — acceptable per grill decision; document that
  only `only`/`timeout`/`json`/`shallow`/`jobs` are the useful keys.
