        # Context

`forge-cli` today runs a generic pipeline: clone/pull → `.env` → `install.ps1|install.sh`.
Inspection of the real Forge repositories (local checkouts under `E:\projetos\FORJAS`) shows the
assumptions were wrong:

- **No repo ships `install.*`.** All 7 Python repos ship `setup.ps1`/`setup.sh` (portable
  bootstrap: resolve Python → isolated venv → wheel → launcher + manifest). Current CLI reports
  `[AVISO]` on every one of them.
- **`forge-portal` is an Angular app** (`package.json` + `package-lock.json`, scripts
  `ng serve/build/test`) and ships **no** shell script — it needs `npm`.
- **No repo has `.env.example`.** `platform-forge` ships `config.example.yaml`; spark-forge-*
  and forge-doctor-data ship `examples/` dirs. `.env` provisioning (lf-0002) stays, but config
  examples are a real convention to handle.
- Each Python repo exposes a CLI bin (from `[project.scripts]`): `theforge`,
  `sparkforge-aws`, `sparkforge-azure`, `platformforge`, `apiforge`, `forge-doctor-api`,
  `forge-doctor-data`. Portal has local `ng` after install.

# Grill Gate

Decisions locked with the repo owner:

- **Mechanism: convention pipeline.** Per-repo instructions are auto-detected from files present
  in the checkout (setup/install scripts, `package.json`, `*.example.*` configs, `.env`).
  No hardcoded step lists — the pipeline adapts as repos evolve. Recommended option accepted.
- **Scope (all four accepted):**
  1. Core per-repo setup: `setup.*` + `install.*` detection, `npm ci` for package.json repos,
     `*.example.*` config copy, `.env` provisioning (lf-0002 rules preserved).
  2. Post-setup verify: optional per-repo `verify` command in the catalog; soft-fail warns,
     never blocks.
  3. git pull hardening: `--ff-only`, dirty-tree detection warns and continues.
  4. Live script output: stream setup-script output via clack `taskLog` instead of a silent spinner.
- **npm mode: `npm ci`** when a lockfile is present (`npm install` as fallback without one).
- **Implementer: Devin** (this session); spec language and UI remain PT-BR.

# Pipeline (per repo, in order)

1. **Sync**
   - Missing dir → `git clone`.
   - Existing dir with `.git` → `git status --porcelain` first; non-empty → note
     "alterações locais detectadas" and still attempt `git pull --ff-only`.
     Pull failure → **warning** ("pull falhou, seguindo com a versão local"), continue to setup.
   - Existing dir without `.git` → `[AVISO]`, skip setup (current rule preserved).
2. **`.env`** — unchanged from lf-0002 (never overwrite; copy `.env.example`; else PT-BR stub).
   Env failure → `[ERRO]`, skip remaining steps.
3. **Config examples** — root-level files matching `*.example.*` excluding `.env.example`
   → copy to the name without `.example.` (e.g. `config.example.yaml` → `config.yaml`).
   Existing target → skip (never overwrite). Notes recorded per copy.
4. **Setup script** — first existing of `setup.ps1`, `install.ps1` (win32) /
   `setup.sh`, `install.sh` (nix). Run via `powershell -File` / `bash`, output **streamed live**
   through clack `taskLog`. Non-zero exit → `[ERRO]` with exit code; skip verify.
5. **npm** — `package.json` present → `npm ci` if `package-lock.json` exists else `npm install`
   (streamed via `taskLog` as well). Runs after the script step regardless of whether a script ran.
   Failure → `[ERRO]`; skip verify.
6. **Verify** — if the catalog entry defines `verify` (argv), run it. Exit 0 → note
   "verificação OK". Non-zero/missing bin → **warning** "verificação não confirmada", never `[ERRO]`.

Phase messages update accordingly: `Sincronizando` → `Provisionando .env` →
`Copiando configs` → `Executando <script>` → `npm ci` → `Verificando`. `em Xs` timing stays.
